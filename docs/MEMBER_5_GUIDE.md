# מדריך והכנה להגנה - חבר צוות 5 (תגובות, אנליטיקות, הגבלת ספאם ו-Seeder)

מסמך זה מרכז את כלל המידע הטכני, הרציונל הארכיטקטוני, ומדריך שלב-אחר-שלב להדגמה בפני המרצה במהלך ההגנה על הפרויקט.

---

## 🎯 תחומי האחריות של חבר צוות 5

1. **מודל תגובות (Comment) וממשק AJAX**:
   - מודל Mongoose עם אינדקסים משולבים ואינדקס טקסטואלי לחיפוש.
   - ממשק לקוח ב-Vanilla JS לביצוע הוספת תגובה מיידית ללא רענון עמוד (AJAX).
   - תמיכה בפעולות CRUD מלאות (יצירה, קריאה, עדכון ומחיקה ע"י עורך).

2. **מנגנון הגבלת תגובות בצד השרת (Anti-Spam Rate Limiter)**:
   - חסימת משתמש (אורח) מלהגיב יותר מ-3 תגובות בדקה מאותו מכשיר/IP.
   - מימוש מבוסס מסד נתונים המבטיח **עמידות מלאה ל-Restart של השרת**.
   - החזרת קוד שגיאה תקני `HTTP 429 Too Many Requests` עם כותרת `Retry-After` והודעה ברורה בעברית.

3. **מודל נתוני צפייה וסטטיסטיקות (ViewStat / Scalable Analytics)**:
   - מימוש בשיטת **Time-Bucket Aggregation** (דליי זמן שעתיים) ועדכונים אטומיים באמצעות אופרטור `$inc` ו-`upsert`.
   - מותאם במיוחד לעבודה בעומסי תעבורה כבדים (אלפי קוראים במקביל) ללא נעילות I/O וללא יצירת מיליוני רשומות נפרדות.
   - תמיכה בפעולות CRUD מלאות (כולל חיפוש טקסטואלי, עדכון ומחיקה).

4. **אזור סטטיסטיקות העורך (Impact Analytics Visualizer)**:
   - דשבורד גרפי אינטראקטיבי מבוסס **Chart.js** (מ-CDN לפי דרישות הקורס).
   - הצגת עקומת צפיות לאורך ציר הזמן.
   - סימון ברור של נקודות פרסום ראשוני ונקודות עדכון תוכן ע"י עורך (Milestones).
   - חישוב והצגת השפעת העדכון על היקף הצפיות (Before vs. After Comparison & % Growth).

5. **סקריפט הזנת נתוני דמה (Database Seeder)**:
   - סקריפט `npm run seed` המייצר מעל **520 כתבות** בכל הקטגוריות והסטטוסים.
   - יצירת משתמשי דמה (עורכים וכתבים) עם סיסמאות מוצפנות ב-`bcrypt`.
   - יצירת 25 כתבות שעברו עדכוני גרסה מרובים לאחר הפרסום.
   - הזנת נתוני צפייה היסטוריים ומאות תגובות קוראים להמחשת כלל יכולות המערכת.

## 🏗️ שאלות צפויות מהמרצה וכיצד לענות עליהן

### שאלה 1: "כיצד המערכת שלכם עומדת בעומס של אלפי קוראים במקביל בעת רישום צפיות?"
**התשובה:**
> *"במקום לבצע Insert של מסמך חדש עבור כל צפייה בודדת (דבר שהיה יוצר עומס כתיבה אדיר וטבלה עם מיליוני שורות), השתמשנו בתבנית Time-Bucket Aggregation שנלמדה בשיעורי MongoDB.
> לכל כתבה ושעה מוגדר דלי זמן ייחודי (`timeBucket`, למשל `2026-09-30-11`). בעת כניסת קורא מתבצע עדכון אטומי יחיד באמצעות אופרטור `$inc` ו-`upsert`:
> `ViewStat.updateOne({ article, timeBucket }, { $inc: { viewCount: 1 } }, { upsert: true })`.
> פעולה זו אטומית לחלוטין ברמת מסד הנתונים, אינה נועלת את האוסף, ודורשת משאבי רשת וזיכרון מינימליים ביותר."*

---

### שאלה 2: "איך מימשתם את הגבלת 3 התגובות בדקה? מה קורה אם השרת קורס או מבצע Restart?"
**התשובה:**
> *"מנגנון ה-Rate Limiting מומש ב-Middleware בצד השרת (`commentRateLimiter.js`).
> כדי לעמוד בדרישת המרצה שהמערכת תמשיך לתפקד בצורה זהה גם לאחר Restart של השרת, איננו שומרים את מוני התגובות בזיכרון ה-RAM של Node.js, אלא בודקים ישירות במסד הנתונים את כמות התגובות שנוצרו ב-60 השניות האחרונות:
> `Comment.countDocuments({ clientIp, createdAt: { $gte: oneMinuteAgo } })`.
> הודות לאינדקס המשולב שהגדרנו במודל `{ clientIp: 1, createdAt: -1 }`, שאילתה זו חוזרת תוך מילי-שניות בודדות. אם השרת עובר אתחול באמצע העבודה, המידע ב-MongoDB נשמר והמגבלה של 3 תגובות בדקה נותרת אכיפה במלואה!"*

---

### שאלה 3: "האם כל המודלים שלכם תומכים ב-CRUD מלא ובחיפוש?"
**התשובה:**
> *"כן, בהחלט. כל ארבעת המודלים תומכים ב-Create, Read (כולל חיפוש טקסטואלי ודפדוף), Update ו-Delete:
> - **Comment**: יצירת תגובה ב-POST, קריאה וחיפוש טקסטואלי (`$text`) לפי תוכן ושם מגיב, עריכת תגובה ב-PUT, ומחיקת תגובה ע"י עורך ב-DELETE.
> - **ViewStat**: רישום אטומי ב-POST, חיפוש ושליפה ב-GET, עדכון רשומה ב-PUT, ומחיקה ב-DELETE.
> כל נתיבי ה-API מתוכננים לפי עקרונות ה-REST ומחזירים קודי סטטוס תקניים (200, 201, 400, 401, 403, 404, 429)."*

---

### שאלה 4: "איך עובד גרף ה-Impact Analytics?"
**התשובה:**
> *"נתיב ה-API `GET /api/analytics/article/:id` שולף את רשומות הצפייה השעתיות של הכתבה וממיין אותן כרונולוגית.
> במקביל, הוא קורא ממודל ה-Article את מערך ה-`revisionsHistory` שבו שמורים התאריכים המדויקים שבהם עורך אישר ופרסם עדכונים.
> השרת מחשב את ממוצע הצפיות לשעה לפני העדכון האחרון מול ממוצע הצפיות לשעה אחריו, ואת אחוז השינוי (% Growth).
> בצד הלקוח, ספריית Chart.js (שהוטענה כ-CDN כפי שנלמד בהרצאה 3) מרנדרת עקומה רציפה, ומציגה מתחתיה את אבני הדרך (Milestones) עם פירוט מדויק של השינוי."*

## 🎬 מדריך להדגמה מעשית שלב-אחר-שלב בפני המרצה

### שלב 1: איפוס והזנת נתונים
1. פתחו טרמינל והריצו:
   ```bash
   npm run seed
   ```
2. הראו למרצה את פלט הטרמינל המרשים:
   - 520 כתבות נוצרו בהצלחה (370 פורסמו, 60 טיוטות, 50 ממתינות לאישור, 40 הוחזרו לתיקונים).
   - נוצרו 6 משתמשים עם סיסמאות מוצפנות ב-`bcrypt`.
   - נוצרו 25 כתבות עם היסטוריית עדכונים כפולה ומרובעת.

### שלב 2: הדגמת גרף ה-Impact Analytics
1. הפעילו את השרת:
   ```bash
   npm start
   ```
2. פתחו את הדפדפן בכתובת:
   ```
   http://localhost:3000/analytics.html
   ```
3. בחרו בכתבת הדגל: **"דעה: החוסן הכלכלי של ישראל מול אתגרי השעה (מהדורה #151)"**.
4. הצביעו על כרטיסי המדדים:
   - סה"כ צפיות.
   - מספר עדכוני עורך (2 עדכונים).
   - ממוצע צפיות לפני העדכון מול אחריו, ואחוז הצמיחה הירוק (+%).
5. הראו את עקומת ה-Chart.js: הקפיצה הברורה בכמות הצפיות לאחר כל נקודת עדכון של עורך!
6. לחצו על כפתור **"+10 צפיות מהירות"** והראו שהנתונים מתעדכנים מיידית.

### שלב 3: הדגמת תגובות AJAX ללא רענון עמוד
1. באותו דף למטה, מלאו שם מגיב ותוכן תגובה.
2. לחצו על **"שלח תגובה (AJAX)"**.
3. הדגישו בפני המרצה שהתגובה נוספה לראש הרשימה **באופן מיידי ללא ריענון של העמוד** (נעשה באמצעות `fetch` ו-DOM Manipulation ב-Vanilla JS).

### שלב 4: הדגמת הגנת ספאם (3 תגובות בדקה לאותו מכשיר)
1. לחצו על כפתור הבדיקה האוטומטית: **"בצע בדיקת הצפת ספאם (4 תגובות מהירות)"**.
2. הראו את הפלט בתיבת הלוג:
   - תגובה 1: אושרה (201)
   - תגובה 2: אושרה (201)
   - תגובה 3: אושרה (201)
   - **תגובה 4: נחסמה מיידית עם שגיאת HTTP 429 Too Many Requests!**
3. הראו את הבאנר האדום עם טיימר הספירה לאחור שנפתח בדף.

### שלב 5: הדגמת שרידות לאחר Restart של השרת
1. מיד לאחר שהמשתמש נחסם ב-Step 4, עצרו את השרת בטרמינל (`Ctrl+C`).
2. הפעילו את השרת מחדש (`npm start`).
3. נסו לשלוח תגובה נוספת באותה דקה בדפדפן.
4. הראו למרצה שהשרת **עדיין זוכר את החסימה** ואינו מאפשר לפרסם תגובה נוספת עד תום הדקה!
